# GraphRAG アーキテクチャ考察 — 抽出層の忠実度を上げると何が変わるか

グラフ抽出を構造化出力（JSON）へ移行し、ローカル LLM（Gemma 4）でも書式由来の脱落なく
entity / relationship を抽出できるようにした（[`ENTITY_RELATIONSHIP.md`](ENTITY_RELATIONSHIP.md)）。
その状態で GraphRAG の QA 品質を測った結果（[`TAGORE.md`](TAGORE.md)）に基づき、**抽出層（グラフ）の
忠実度を上げると GraphRAG の何が変わり、何が変わらないか**を整理する。

## 3 層構造

GraphRAG の成果物は抽象度の異なる 3 層から成り、**上に行くほど集約・横断に強い代わりに忠実度が
落ちる**。Local は主に下 2 層（特に生テキスト）に、Global は最上層の要約に依存する。

| 層 | 構造化 | 忠実度 | 到達手段 |
| --- | --- | --- | --- |
| `text_units`（チャンク） | 低（生文） | 高（原文ほぼそのまま） | 埋め込み類似検索 |
| `entities` / `relationships`（グラフ） | 中（三つ組に近い） | 中（抽出は選択的・説明は要約） | グラフ辿り＋エンティティ検索 |
| `community_reports`（要約） | 高（テーマ単位） | 低（大幅に圧縮） | Map-Reduce |

抽出層の忠実度向上が効くのは**中間層（グラフ）の密度**である。最下層（生テキスト）は
チャンキングが同じなら不変で、最上層（要約）は中間層を集約した派生物にすぎない。
したがって抽出を改善しても、QA が変わるのは「**原文への索引（エンティティ／関係を辿る経路）が
太くなる**」ことによるのであって、「原文をより多く持つから」ではない。

## 抽出層の忠実度を上げて消えた限界

- **出力フォーマット遵守の失敗**。タプル区切り（`<|>`）の崩れによる relationship の silent drop は、
  構造化出力（grammar-constrained decoding）が**デコーダ側で書式を強制**するため原理的に消えた。
  これが relationship 生存率を押し上げ、グラフ密化の主因になった。これは「Gemma の限界が**出力書式**に
  現れていた」部分であり、モデルの推論力に手を付けずに除去できた唯一の種類の限界である。
- **型（entity_types）のドメイン不一致の緩和**。prompt-tune で題材に合う型を導出すれば、汎用の
  既定型では拾えなかった事実もノード化される。ノード化される事実の幅は広がる。

## 抽出層の忠実度を上げても残る限界

- **型に載らない数量・属性**。型をドメイン最適化しても、「8 本の太い金の腕輪＋1 個のダイヤの腕輪」の
  ような数量・修飾はノード／エッジの属性に乗らず、生チャンクの中にしか残らない。抽出層をいくら
  密にしても、最下層の検索（チャンク粒度・埋め込み精度）で拾えなければコンテキストに届かない。
- **クレーム層が空**。covariates（`extract_claims`）を無効にすると、エンティティに紐づく事実文を
  拾う層が無く、細部の命題はグラフに昇格しない。
- **要約層の圧縮（Global の天井）**。コミュニティが増えても、Global が依拠する要約は高レベルの
  テーマ記述で、細部の因果は圧縮で落ちる。**density を上げても方式そのものの天井が先に来る**。

## 含意：ボトルネックの所在が下流へ移る

GraphRAG のグラフは「文章の完全な意味表現」ではなく、**顕著なエンティティ間を辿るための
ナビゲーション索引**である。この像は抽出層を密にしても変わらないが、**索引の密度が上がると
ボトルネックの所在が下流へ移動する**。

- **Local**: 律速が「抽出（出力フォーマット）」から「**検索（チャンク粒度・埋め込み精度）**」へ
  下りる。正しいコンテキストさえ渡れば LLM は答える。残る失敗は最下層の検索リコールに起因し、
  **GraphRAG の構造的限界が LLM の性能限界より先に来る**。
- **Global**: 依然「**要約方式の天井**」が律速で、これはグラフ密化では解けない。俯瞰的な
  「テーマは何か」型に向く方式であって、細部の事実 QA とは噛み合わない。

つまり「LLM の限界が抽出の**書式**に出ていた部分は構造化出力で取り除け、GraphRAG 本来の検索性能が
引き出せた。その結果 Local では律速が検索（構造）側へ移り、Global では方式の天井が残った」と
整理できる。

## 残る手当て（忠実度をさらに上げる方向）

いずれも忠実度と索引コストのトレードオフ上の選択であり、「全文をグラフ化する」理想に近づくほど
索引は重くなる。効果が見込める順に：

1. **クレーム抽出（covariates）の有効化** — 型に載らない事実文を拾う層を足す。
2. **チャンクの細分化／命題単位の索引化** — 最下層の検索リコールを上げる。
3. **グラフ×ベクトルのハイブリッド検索** — エンティティ経由で拾えない細部を埋める。
4. **より高性能な LLM での再実行** — 残存する LLM 要因（保守的な棄権など）の切り分け。
